# Developing

This document gives some pointers and tips for those interested in contributing to this project.

If you notice that this document is outdated, or if something isn't clear to you, please [open an issue](https://github.com/solidity-parser/parser/issues/new)!

## Architecture

This package wraps a parser generated by [ANTLR](https://www.antlr.org/). In this guide, "parser" means the public API exported by this package, and "generated parser" means the code produced by ANTLR.

The grammar lives in the [solidity-parser/antlr repository](https://github.com/solidity-parser/antlr), included here as a Git submodule at `antlr/`. Its `Solidity.g4` file defines the syntax accepted by the generated parser. Grammar changes belong in that repository; consuming them here involves updating the submodule commit, regenerating the parser, and adapting the AST builder if needed.

For example, changing the order of state variables in the public AST may only require a change to the AST builder. Supporting a new Solidity keyword usually also requires a grammar change.

The public entry point is [`src/index.ts`](src/index.ts), which re-exports the API from [`src/parser.ts`](src/parser.ts). The `parse()` implementation runs the generated lexer and parser in [`src/antlr/`](src/antlr/), then uses [`src/ASTBuilder.ts`](src/ASTBuilder.ts) to turn their parse tree into the public AST. `ASTBuilder` is a [visitor](https://en.wikipedia.org/wiki/Visitor_pattern); its `visit...` methods handle grammar contexts and construct the node types declared in [`src/ast-types.ts`](src/ast-types.ts). Its `_addMeta()` helper adds location and range information when requested.

## Setup

Install Node.js and npm, then clone the repository and install its dependencies:

```bash
git clone https://github.com/solidity-parser/parser.git solidity-parser
cd solidity-parser
git submodule update --init
npm ci
```

The generated TypeScript parser is checked in, so editing the wrapper and running the Node.js tests do not require ANTLR tooling. Grammar regeneration requires the additional setup below.

## Updating the grammar

We use [antlr4-tools](https://github.com/antlr/antlr4-tools) to run ANTLR. Install it with Python 3 and ensure its `antlr4` and `antlr4-parse` commands are on your `PATH`:

```bash
python -m pip install antlr4-tools
```

The tool uses Java and can download a Java runtime and the ANTLR JAR on first use if needed. To select a generator version, set `ANTLR4_TOOLS_ANTLR_VERSION`; keep it compatible with the `antlr4` runtime version in [`package.json`](package.json).

After editing `antlr/Solidity.g4` or updating the submodule to a new grammar commit, run:

```bash
npm run antlr
```

This generates TypeScript files under `src/antlr/` and runs the token-string generation script. Update `ASTBuilder.ts` and the AST types for any changed contexts or public nodes. Include the regenerated files and the updated submodule commit when submitting a grammar update to this repository.

## Building and testing the parser

For wrapper changes that do not need grammar regeneration, use:

```bash
npm run build:node
npm run build:browser
npm run generate-types
```

These commands build the CommonJS bundle at `dist/index.cjs.js`, the browser bundle at `dist/index.umd.js`, and the TypeScript declarations under `dist/`, respectively. `npm run build` runs all three after regenerating the grammar, so it also requires the ANTLR setup.

Run the Node.js tests with:

```bash
npm run test:node
```

Mocha loads the TypeScript tests in `test/` through `ts-node`; they exercise the source directly. Add regression tests there when changing parser behavior.

The browser tests in `browser-test/` use the built browser bundle:

```bash
npm run build:browser
npm run test:browser
```

Karma launches the headless Chrome supplied by Puppeteer, so its browser download must be available. `npm test` runs both the Node.js and browser suites; build the browser bundle first. Run `npm run lint` to check ESLint and Prettier formatting.

## Quick testing

Build the Node.js bundle, then start a REPL from the repository root:

```bash
npm run build:node
node
```

```javascript
const parser = require('.')
const ast = parser.parse('contract Foo {}')
console.log(ast.children[0].name) // Foo
```

Rebuild the bundle after source edits before testing it with `require('.')` again. A running REPL also caches loaded modules; restart it to pick up the new bundle.

## Understanding the generated parser

ANTLR produces a parse tree that follows the grammar closely. The public AST removes syntax details and represents Solidity constructs as typed nodes. To change that conversion, follow the corresponding context through the `visit...` methods in `ASTBuilder.ts`.

### Example 1: PragmaDirective

The grammar defines a pragma directive as:

```text
pragmaDirective : 'pragma' pragmaName pragmaValue ';' ;
```

`visitPragmaDirective()` receives a `PragmaDirectiveContext`, with `pragmaName()` and `pragmaValue()` accessors. It uses `_toText()` to read their text. For a version pragma, it joins the version components with spaces to normalize an expression such as `>= 0.5.0  <0.7.0` to `>=0.5.0 <0.7.0`.

The method constructs a node with `type: 'PragmaDirective'`, `name`, and `value`, then returns it through `_addMeta()`.

### Example 2: FunctionCall

`visitFunctionCall()` receives a `FunctionCallContext` and reads its `functionCallArguments()`. The relevant grammar rules are:

```text
functionCall : expression '(' functionCallArguments ')' ;

functionCallArguments
  : '{' nameValueList? '}'
  | expressionList? ;

nameValueList
  : nameValue (',' nameValue)* ','? ;

nameValue
  : identifier ':' expression ;
```

For a positional call such as `f(1, 2)`, `expressionList()` supplies an `expression_list()`. The builder visits each expression with `visitExpression()` to populate the `arguments` array.

For a named call such as `f({a: 1})`, `nameValueList()` supplies a `nameValue_list()`. The builder collects each value in `arguments`, its name as text in `names`, and its identifier node in `identifiers`. The latter two arrays are empty for positional calls.

The resulting `FunctionCall` node also contains the called `expression`, converted with `visitExpression()`, and is returned through `_addMeta()`.

## Visualizing the ANTLR parse tree

With `antlr4-tools` installed, use its grammar interpreter to inspect the parse tree directly. From the `antlr/` directory, create an `example.sol` file containing:

```solidity
contract Example is Base1, Base2(0) {}
```

Then run:

```bash
antlr4-parse Solidity.g4 sourceUnit -gui example.sol
```

This opens the parse tree in a Java GUI. Use `-tree` instead of `-gui` for text output. This is the grammar's parse tree, before the conversion performed by `ASTBuilder`.
